This guide helps security analysts and detection engineers use AI Parsing in Google Security Operations to build custom parsers from scratch or create parser extensions that augment existing parsers. Using natural language prompts and vendor documentation, you can map raw logs to the Unified Data Model (UDM) without writing complex parser syntax or regular expressions.
## Choose between AI custom parsers and AI parser extensions
The following table compares the Create Parser with AI and Write Extension with AI capabilities in AI Parsing:    Feature aspect Create Parser with AI Write Extension with AI     Output A complete, standalone custom parser An extension layered on an existing parser   Primary use case New or unsupported log sources, or a full parser rewrite Adding or fixing specific fields on a working parser   Input Log type, ingested raw logs, and optional documentation links Log type, sample raw log, and a prompt describing the fields to map
## Key terminology
AI Parsing: The suite of AI-assisted parsing capabilities in Google SecOps, including AI custom parser generation (Create Parser with AI) and AI parser extensions (Write Extension with AI). Unified Data Model (UDM): The standard data structure used in Google SecOps to store and analyze log data.
## Before you begin
Before using AI Parsing, make sure that you meet the following prerequisites:  Confirm that AI Parsing capabilities are enabled for your Google SecOps instance. If you don't see the Create Parser with AI or Write Extension with AI options, contact your Google SecOps representative. For AI parser extensions, verify that the target log type already has an active prebuilt or custom parser, and prepare a sample raw log to test your extraction. For AI custom parser generation, ingest a representative sample of the log source before you start. The Parser Agent learns from logs that you have already ingested for the selected log type. If no logs are found for the log type, generation can't start. Failed start attempts don't count against your quota. For AI custom parser generation, prepare one to five publicly accessible links to the vendor's log format reference, such as a field dictionary, event schema, or log samples page (recommended). Comprehensive documentation is the single biggest factor in parser quality.
## Create a custom parser with AI
Create Parser with AI builds a complete custom parser for a log source from scratch. You select a log type and optionally provide links to the vendor's log documentation. The Parser Agent samples your ingested logs, researches the log schema, plans the raw-field-to-UDM mapping, and writes the parser code in JavaScript. You then review the result and refine it using plain-English instructions that reference raw field names and UDM fields. When the output is ready, you submit the parser like any other custom parser.
With AI custom parser generation, you can do the following:  Onboard a log source that has no prebuilt parser, or whose prebuilt parser doesn't fit your log format. Generate a complete parser that covers every distinct log format found in your ingested data, rather than only a single sample. Refine the generated parser through follow-up prompts without writing parser code yourself.
### Start an AI-generated custom parser
In Google SecOps, go to SIEM Settings > Parsers. Click Add New Parser. In the Create New Custom Parser dialog, select the Log Source that you want to parse (for example, `GCP DNS`). Under How will you create the parser?, select Create Parser with AI. Click Create.
### Add product documentation and start generation
Note: Documentation links are optional. If you don't add any links, the research stage searches the web to find the vendor's documentation and infers the schema directly from your raw logs. This approach works well for common, well-documented products. For niche or internal log sources, adding links provides better field coverage.  Optional: In the Parser Agent pane, in the Add product link field, paste a link to the vendor's log documentation and click Add. You can add up to five links. The Documentation counter displays how many links you have added. Click Generate Parser.
#### Guidelines for documentation links
To improve field coverage in the generated parser, follow these guidelines when selecting documentation links:  Provide only public links to vendor documentation. If a link is private or inaccessible, the Parser Agent ignores the link and searches the web instead without failing the generation. Link to pages that describe log fields and event types, such as a log schema, field dictionary, or event reference. Avoid marketing pages or product overviews. Select pages that match the log format you ingest. For example, if you ingest JSON audit logs, link to the JSON audit log reference rather than the syslog reference. Add a link for each event category if the vendor documents different event categories on separate pages (for example, DNS queries, firewall events, and administrator activity).
### Track generation progress
When custom parser generation begins, the status changes to GENERATING IN PROGRESS. The generation process consists of the following stages:    Stage Agent action Output passed to next stage     Fetching raw logs The agent samples your ingested logs for the log type. It clusters the logs to select a set of example logs that covers every distinct log format and event shape. Representative example logs   Research documentation The agent reads the documentation links you provided, or searches the web if you didn't provide links. It combines that information with the example logs to build a log schema and field dictionary. Log schema and field dictionary   Create a mapping plan The agent identifies each event type in the logs and plans how each raw log field maps to the corresponding UDM field. Mapping plan from raw field to UDM field for each event type   Generate parser code The agent converts the mapping plan into JavaScript parser code. It tests the code against the example logs and resolves errors until the parser runs cleanly. Ready-to-review parser    Note: The generation process typically takes 30 to 90 minutes, depending on the number of distinct log formats, the complexity of the log source, and the size of the log schema. You don't need to keep the page open. Click Close and return to SIEM Settings > Parsers later. When generation completes, the parser appears in the list with an AI GENERATED badge.
If parser generation fails because no logs are found for the selected log type, ingest raw logs for that log type before you start generation again. For any other generation failure, no manual triage options are available. Trigger a new generation session. If the failure persists, contact Support to open a support case.
### Review and refine the custom parser
When custom parser generation finishes, the status changes to AI GENERATED and the page displays the following panes:  Parser Agent: Displays the Refine Parser with AI prompt field where you can enter follow-up instructions. Parser Code: Displays the generated JavaScript parser code for review. The generated code is read-only before submission. To modify the logic, enter a prompt in the Refine Parser with AI field. Raw Log: Displays sample raw logs for the log type. You can click edit Edit to paste your own log line, or click refresh Refresh to load other samples. Show UDM Output: Runs the current parser code against the raw log and displays the resulting UDM event so you can verify each mapping.
#### Review the generated output
Before activating the parser, review the generated mappings across your sample logs:  Load several raw logs, including each event type that you want to parse, and click Show UDM Output for each log. Verify that the parser maps raw log fields to the appropriate UDM fields and populates their values accurately (for example, event metadata, entity fields such as `principal` and `target`, and security result fields). Check for any important raw fields that remain unmapped.
#### Refine the custom parser with AI
If a mapping is incorrect or missing, enter an instruction in the Refine Parser with AI field and click Confirm. The Parser Agent updates the existing parser rather than starting over and preserves all mappings that you didn't mention. Each refinement creates a new version of the parser code that you can review.
Follow these guidelines to craft effective refinement prompts:  State both the raw source field (or a sample value from the log) and the exact target UDM field path. Group related changes together, and avoid mixing unrelated fixes in a single long prompt. Enclose exact strings from the raw log with single quotation marks, such as `'NXDOMAIN'` or `'allow'`. State conditional mappings explicitly using an `if ... then ... otherwise ...` structure when a mapping depends on a field value. Instruct the agent to map vendor-specific attributes that don't have a matching UDM field to `additional.fields` with a clear key name.
The following table provides example refinement prompts for `GCP DNS` logs:    Goal Example prompt     Fix an incorrect mapping `"Map jsonPayload.sourceIP to principal.ip instead of target.ip."`   Add a missing field `"Map jsonPayload.vmInstanceName to principal.hostname."`   Map a nested or repeated value `"Map jsonPayload.queryName to network.dns.questions.name and jsonPayload.queryType to network.dns.questions.type."`   Apply conditional logic `"If jsonPayload.responseCode is 'NXDOMAIN', set security_result.summary to 'Domain does not exist'. Otherwise, leave it empty."`   Set the event type `"Set metadata.event_type to NETWORK_DNS for all DNS query logs."`   Map a vendor-specific field `"Map jsonPayload.alias_query_response_code to additional.fields with key 'alias_query_response_code'."`   Remove a mapping `"Stop mapping jsonPayload.protocol to network.application_protocol."`    Note: You can't edit the generated code directly in the Parser Code pane before submission. After you submit and activate the parser, you can edit its code manually like any other custom parser.
### Submit and activate the custom parser
When the UDM output is accurate, click Submit to save and activate your generated custom parser.
To abandon the draft parser instead, click Discard. To remove a saved AI-generated custom parser later, open the parser and click Delete under Delete Custom Parser. Caution: AI custom parser generation is an experimental feature. Generated parser quality can vary. Always review the UDM output for each event type and validate the parser before you activate it in production.

## Create a parser extension with AI
When a default log parser in Google SecOps parses your log source, it might omit customer-specific custom attributes, optional fields, or specialized telemetry. Using AI parser extensions (Write Extension with AI) lets you do the following:  Extract additional fields from raw logs and map them to standard UDM fields or custom `additional.fields`. Apply conditional logic and value transformations, such as mapping string actions to UDM enumerated types. Refine generated extensions interactively across multi-turn chat sessions without starting from scratch.
## Key terminology
Unified Data Model (UDM): The standard data structure used in Google SecOps to store and analyze log data.
## Before you begin
Before you begin, confirm the following prerequisites are met:  Usage quotas: You can run a maximum of 10 AI Parser Extension generation sessions per 24-hour window, with up to 5 messages per session.
## Best practices for crafting prompts
To get accurate parser extensions, follow these prompting guidelines:  Specify source and target explicitly: Clearly state which part of the raw log to extract and which exact UDM field path it populates, for example, `principal.ip`, `target.user.email_addresses`, or `security_result.action`. Use quotes for exact match literals: When referring to literal strings, delimiters, or sample values in unstructured logs, enclose them in quotation marks, for example, `"198.51.100.0"` or `"allow"`. Handle custom fields by using `additional.fields`: For proprietary or vendor-specific attributes that don't have a dedicated UDM field, instruct the AI to map them into `additional.fields` with a clear key name, for example, `additional.fields["application"]`.
### Generate a parser extension
You can start the parser extension workflow from either of the following locations in Google SecOps:  Parsers settings page: Go to the Parsers page to select and extend any existing log parser. Search page: When investigating logs on the Search page, open the extension creation flow directly from an event with unparsed fields.
To generate a parser extension from the Parsers page, follow these steps:  In Google SecOps, navigate to the Parsers settings page. Search for the log type you want to extend. Click the menu next to the parser and select the option to extend it. In the RAW LOG field, paste a sample of the log you want to parse. In the Extension Method section, select the Generate with AI tab. In the prompt field, enter a plain English description of the extraction.
Click Confirm.
The system generates the extension code and updates the UDM Output pane.
### Refine the parser extension
You can build and refine your parser extension iteratively across multi-turn chat sessions. When you submit a follow-up prompt, the AI applies your new instructions on top of the previously generated extension. Existing mappings and conditional logic from earlier turns are preserved automatically unless you explicitly ask to override or remove them. Note: Sessions don't persist after you leave the page. To avoid losing your work, complete or save your extension before you leave the page.  In the prompt field, enter a follow-up instruction to adjust the generated code. Click Confirm. After each prompt, preview the generated extension code, inspect sample UDM outputs, and confirm or adjust the logic.  Note: To correct a mistake from a previous turn, state what to change in plain English, for example, `"Change the target field for callerIp from target.ip to principal.ip"`.
The following example workflow shows how iterative refinement builds a parser extension across multiple turns:  Turn 1 (initial extraction):  User prompt: "Extract source IP '198.51.100.0' to principal.ip and destination IP '198.51.100.1' to target.ip." Result: The AI generates an extension mapping `principal.ip` and `target.ip`.  Turn 2 (additive mapping):  User prompt: "Also map virtual system string `vsys1` to `observer.administrative_domain`." Result: The AI updates the extension to map `observer.administrative_domain` while maintaining the IP mappings from turn 1.  Turn 3 (conditional refinement):  User prompt: "In addition, map action string `allow` to `security_result[0].action` as ALLOW." Result: The AI incorporates the conditional action enumeration mapping on top of all previous extractions.
### Validate the parser extension
Click Validate. Review the validation metrics after the process completes.

#### Conditional logic prompts
Describe conditional logic to normalize raw log values to specific UDM enumerations.  Enumeration normalization: `"If the firewall action in the log is 'allow', set security_result.action to ALLOW; otherwise set security_result.action to BLOCK."` Conditional field mapping: `"If the protocol is 'icmp', map the ICMP type and code into network.icmp.type and network.icmp.code."` Status mapping: `"When the log status contains 'success' or '0', set security_result.severity to INFO; if it contains 'error', set it to ERROR."`
## Usage limits
To maintain optimal performance and resource availability, AI Parsing capabilities enforce the following default usage quotas:  Each customer is allotted a maximum of 10 AI Parser Extension generation sessions per 24-hour window. Within a single session, you can only send up to 5 messages, including your initial prompt and subsequent refinement turns, to craft and refine your parser extension.
If you reach the turn or message limit for a session, you can submit or save your current work, or start a new session (subject to the daily session quota). For custom parsers, after you submit and activate the parser, you can edit its code manually like any other custom parser.
